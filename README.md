# 交易反欺诈数据挖掘与风险决策

比较类别加权逻辑回归与 XGBoost 对欺诈交易的识别效果，将风险分数转换为放行、人工复核和拦截三种决策，并在后续时间段的测试集冻结评估。

项目使用公开信用卡交易数据，包含数据质量检查、时间切分、不平衡分类、模型比较、特征重要性和成本敏感策略；中文 Streamlit 看板用于展示结果。

## 项目展示与结果分析

以下四张图片为 **2026-10-23 实际运行的 Streamlit 看板截图**，使用公开信用卡 CSV 的训练报告，与 `reports/latest.json` 对应。点击图片可查看原图。重新运行训练后，应同步更新截图和分析中的数值。

### 1. 数据概览：明确样本结构与验证边界

[![数据概览：交易规模、质量检查、时间切分与相对小时画像](docs/images/dashboard-overview.png)](docs/images/dashboard-overview.png)

284,807 笔交易中有 492 笔欺诈，占比约 **0.173%**，属于极度不平衡分类任务。单看准确率容易忽略欺诈漏报，因此项目使用 AP 评估风险排序，并同时报告精确率、召回率和混淆矩阵。

训练、验证和测试集按交易时间依次划分为 192,974、47,995、43,838 笔；同一时间戳不会跨集合。数据审计发现 1,081 行完全重复记录，本版本保留原始行并披露问题。相对小时画像用于描述样本，不代表真实钟点；风险分数集中在低分区，也不能单凭这一分布判断模型有效，更不能将未校准的分数当成真实欺诈概率。

### 2. 模型比较：依据验证集选模型，在后续时段评估

[![模型比较：验证集 AP 与冻结模型的测试集指标](docs/images/dashboard-models.png)](docs/images/dashboard-models.png)

类别加权逻辑回归的验证集 AP 为 **0.8036**，类别加权 XGBoost 为 **0.8193**，相差约 **0.0157**，因此本次实验选择 XGBoost。这个差异来自一次固定时间切分，不能据此断言模型在所有时段都更优。

冻结模型后，测试集 AP 为 **0.7675**、ROC-AUC 为 **0.9792**。在分类展示阈值 0.5 下，54 笔欺诈中识别出 41 笔、漏报 13 笔，另有 31 笔正常交易被误报；精确率为 **56.94%**，召回率为 **75.93%**。这说明较高的 ROC-AUC 并不等于没有误报和漏报，业务决策仍需要单独选择阈值。测试集 AP 低于验证集，也提示后续需要更多时间窗口验证稳定性。

### 3. 风险策略：在复核容量约束下评估成本

[![风险策略：冻结阈值、复核容量状态及测试集模拟成本](docs/images/dashboard-policy.png)](docs/images/dashboard-policy.png)

两个策略阈值只使用验证集选择。在测试集上，冻结策略放行 **43,662 笔**、人工复核 **176 笔**、直接拦截 **0 笔**。复核率为 **0.40%**，低于 **2%** 上限；测试集最多允许复核 876 笔，页面明确显示“**未超出**”。复核队列中包含 42 笔欺诈，但人工复核召回率仍按假设的 90% 计算，没有将其视为全部成功拦截。

直接拦截为 0 笔，是因为测试集最高风险分数约为 0.9998228，未达到验证集冻结的拦截阈值约 0.9998300。三段式策略并不保证每个后续时段都产生三类动作；本次没有根据测试集结果重新降低阈值。

按漏放损失 100、误拦成本 6、复核成本 1.5，以及既定复核效果计算，模拟成本为 **1,892.04**，较“全部放行”的 **5,400.00** 下降 **64.96%**。这是与全部放行基线的离线模拟比较，不能表述为相较现有风控系统的提升，也不代表线上资金收益。

### 4. 特征解释：识别模型依赖的变量，说明业务解释边界

[![特征解释：XGBoost 原生重要性与匿名特征的解释边界](docs/images/dashboard-features.png)](docs/images/dashboard-features.png)

本次模型中，匿名特征 **V14、V10、V4** 的原生重要性较高，金额对数特征也进入了前 15 项。该结果用于检查模型关注的变量，不能证明单个特征一定带来性能提升；验证特征增益还需要消融实验。

V1–V28 是经过 PCA 转换的匿名特征，不能直接解释为设备、商户、地域或真实欺诈原因。这一页展示的是全局特征重要性，没有进行单笔交易归因，也不能当作因果分析。

## 快速开始

使用 Python 3.10 或更新版本，以下命令均在项目根目录执行。

### 1. 安装依赖

```bash
python -m pip install -r requirements.txt
```

### 2. 运行公开数据实验

```bash
python run.py train --data data/creditcard.csv --trees 160
```

训练两个模型并将报告写入 `reports/`。运行完成后，可在 `latest.json` 中查看数据来源、选定模型、测试指标和策略成本，文件说明见[文件与输出](#文件与输出)。

训练会覆盖 `reports/latest.json`、`reports/test_scores.csv` 和 `reports/hour_profile.csv`。需要保留不同实验时，请先备份已有报告；切换数据后重新训练，再刷新看板。

### 3. 查看结果

```bash
python run.py dashboard
```

看板读取 `reports/` 中的已有报告，包含“数据概览”“模型比较”“风险策略”“特征解释”四页。报告尚未生成时，先完成上一条训练命令。

如果暂时没有公开数据，可运行 `python run.py demo --rows 12000 --trees 80` 做流程自检；该结果只用于检查代码，不用于简历成果。

## 使用公开信用卡数据

从 [Kaggle Credit Card Fraud Detection](https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud) 下载 `creditcard.csv`，放入 `data/`。项目不自动下载数据，原始 CSV 不纳入版本控制。当前报告对应的来源、下载地址和 SHA-256 记录在 [`data/creditcard.source.json`](data/creditcard.source.json)。

| 字段 | 含义 |
| --- | --- |
| `Time` | 相对起始交易的秒数，用于时间切分和画像 |
| `Amount` | 交易金额 |
| `V1`–`V28` | 匿名主成分特征 |
| `Class` | 标签：0 为正常交易，1 为欺诈交易 |

特征列必须可转换为数值且无缺失，标签必须为 0 或 1。按时间切分后的训练集、验证集和测试集都需同时包含两类交易。文件缺失时程序报错，不会自动替换成合成数据。

## 模型与评估

按 `Time` 排序，以唯一时间戳的 70% 和 85% 位置划定训练、验证、测试边界。同一时间戳的交易保留在同一个集合，因此各集合的交易笔数不一定恰好为 70%、15%、15%。

模型使用 `Amount`、`LogAmount = log1p(max(Amount, 0))` 和 `V1`–`V28`，共 30 个特征。标准化器只在训练集拟合；`Time` 不参与模型训练。相对小时画像由 `Time // 3600` 计算，不能解释为真实钟点。

| 模型 | 不平衡处理 | 主要设置 |
| --- | --- | --- |
| 逻辑回归 | `class_weight="balanced"` | 最多迭代 1,000 次 |
| XGBoost | 训练集负类数 / 正类数作为 `scale_pos_weight` | 深度 4、学习率 0.08，树数由 `--trees` 指定 |

以验证集 AP（平均精确率）选模型。选定模型后，报告测试集 AP、ROC-AUC、Precision、Recall、F1 和混淆矩阵。其中分类指标使用固定阈值 0.5，与下方的策略阈值分别计算。

特征解释对应选定模型：逻辑回归展示标准化系数绝对值，XGBoost 展示原生特征重要性。匿名特征的重要性不表示因果关系，也不能直接还原为商户、设备或客户行为。

## 风险决策与成本

| 分数区间 | 决策 |
| --- | --- |
| 低于复核阈值 | 放行 |
| 达到复核阈值，低于拦截阈值 | 人工复核 |
| 达到拦截阈值 | 拦截 |

程序在验证集分数的候选分位点中搜索两个阈值，要求复核和拦截区间均非空，且复核比例不超过 2%，再选择模拟成本最低的组合。

```text
模拟成本 = 预计漏放欺诈笔数 × 100
         + 预计误拦正常笔数 × 6
         + 人工复核笔数 × 1.5
```

默认假设人工复核召回率为 90%、正常交易误判率为 1%。预计漏放和误拦同时计入复核错误，因此笔数可以为小数。阈值在验证集确定后保持不变，用于测试集，并与全部放行的模拟成本比较。2% 是验证集选策略时的容量约束，测试集或新数据上的复核比例仍可能超限。

## 当前实验结果（公开信用卡 CSV）

本地已按来源文件的 SHA-256 校验值保存数据，并使用固定时间顺序切分。共 284,807 笔交易，其中 492 笔欺诈；训练、验证、测试集分别为 192,974、47,995、43,838 笔。以下数字来自当前 `reports/latest.json`，重新训练后可能随依赖版本变化。

| 验证集模型比较 | AP |
| --- | --- |
| 类别加权逻辑回归 | 0.8036 |
| 类别加权 XGBoost | 0.8193 |

验证集选定 XGBoost。测试集 AP 为 0.7675，ROC-AUC 为 0.9792，Precision 为 0.5694，Recall 为 0.7593，F1 为 0.6508。冻结策略在测试集放行 43,662 笔、复核 176 笔、拦截 0 笔；复核比例为 0.40%，未超过 2% 容量上限。按默认成本假设，模拟成本为 1,892.04，相比全部放行的 5,400.00 下降 64.96%。

数据中发现 1,081 行完全重复记录；本版本保留原始行并将其作为数据质量结果报告，没有静默去重。匿名特征来自 PCA，不能据此声称掌握设备、商户等真实业务字段。

## 使用限制

类别加权模型的输出未经概率校准，应作为风险排序分数使用。漏放、误拦和人工复核的单笔成本及复核准确性均为固定假设；模拟成本不代表真实资金损失或线上收益。

合成数据只用于演示和检查流程。公开信用卡数据中的匿名特征也限制了业务解释；实际使用需要结合交易字段、复核记录和真实成本重新验证。
