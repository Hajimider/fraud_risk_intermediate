# 交易反欺诈数据挖掘与风险决策

**项目类型：** 个人项目｜**岗位方向：** 数据挖掘 / 风控建模

## 简历可用版本

- 基于公开信用卡交易数据（284,807 笔，欺诈 492 笔）搭建反欺诈数据挖掘流程，完成数值校验、缺失值与重复记录审计，并按交易时间划分训练集、验证集和测试集，避免随机切分造成的时间信息泄漏。
- 以类别加权逻辑回归为基线，对比类别加权 XGBoost；使用验证集 AP 选择模型，测试集冻结评估得到 AP **0.7675**、ROC-AUC **0.9792**、Recall **0.7593**、F1 **0.6508**。
- 将风险排序分数转成“放行 / 人工复核 / 拦截”三段式策略，在验证集按复核容量上限和漏放、误拦、人工成本搜索阈值，并在后续测试集复核 **176** 笔（占 **0.40%**，未超过 2% 上限），模拟成本较全部放行下降 **64.96%**。
- 使用 XGBoost 原生特征重要性分析模型关注的变量，补充中文 Streamlit 结果看板、可复现命令入口和自动化测试，支持从数据加载到策略评估的完整复核。

## 技术栈

Python、Pandas、scikit-learn、XGBoost、Streamlit、pytest、时间切分、类别加权、AP/ROC-AUC、成本敏感阈值搜索。

## 面试时应主动说明

- `Time` 在原始数据中是从第一笔交易开始计算的相对秒数，只用于时间切分和相对时段画像，没有被当作真实小时特征；模型使用交易金额、金额对数和 V1–V28 共 30 个特征。
- 公开数据的 V1–V28 是 PCA 后的匿名变量，特征重要性不能直接解释成设备、商户或地域因素；成本和复核效果是离线假设，不代表线上收益。
- 数据审计发现 1,081 行完全重复记录，本版本保留原始行并报告问题，避免在没有业务规则时擅自去重。
- 模型输出未做概率校准，因此项目把它称为风险排序分数；真实上线还需要结合复核反馈、业务成本、概率校准和稳定性监控。

## 可复现命令

```bash
python -m pip install -r requirements.txt
python run.py train --data data/creditcard.csv --trees 160
python run.py dashboard
python -m pytest -q
```

指标来源：`reports/latest.json`；数据来源与 SHA-256 记录：`data/creditcard.source.json`。
