# 面试问答、简历与5分钟讲稿

## 可核实的简历表述

**交易反欺诈数据挖掘与风险决策（ULB，28.5万笔）**

- 以唯一时间戳构造3个扩展验证窗口，对LR和XGBoost以相同候选预算调参，并比较金额原值、对数金额与二者同时输入；按预设的配对AP区间规则选择模型。
- 用同一冻结模型的历史留出分数比较Platt与Isotonic校准，测试AP为0.725（95%区间0.604–0.835），Brier技能分为60.2%，常数基线只使用历史发生率。
- 用MySQL完成画像与数据质量检查，在统一金额加权成本下精确搜索三段阈值；冻结策略的测试模拟成本较全部放行假设低58.9%，并逐组重新优化成本敏感性策略。

以上数字均来自`reports/latest.json`。IEEE-CIS只有流程代码和合成验收，不能写“59万笔已训练”“真实月度AP提升”或“已发现设备欺诈模式”。

## 关键问答

### 为什么不只看ROC-AUC？

总体欺诈率约0.173%，AP更贴近高风险队列质量；同时报告ROC-AUC、阈值下召回/精确率以及成本，防止只用单指标解释策略。当前ROC-AUC为0.9359，低于旧流程，已公开说明实际拟合段变化，不能隐去该结果。

### 如何防止时间泄漏？

唯一时间戳不拆分，各滚动训练段再分为拟合、早停、校准子段，最后15%只测试。变换只在拟合段学习，XGBoost早停不看外部验证或测试标签；冻结模型后用校准段拟合映射，后续不重训基础模型。

### LR为什么胜出？是否证明两模型相同？

调参只使用验证窗口，最近窗口配对AP差值区间含0时按事先规则优先简单模型。这并不证明等效。每类每种金额表达只给3个预设候选，属于有限预算比较，不能声称模型都已充分优化。

### 为什么LR不同时用Amount和LogAmount？

两个变量高度相关会影响系数稳定性。保留三组消融结果，但最终LR只在单金额表达方案中选择；这次选择Amount，不据单个窗口宣称对数金额一定有效。

### 如何解释Brier改善？

类别加权会改变分数的概率尺度，不能把原始到校准Brier下降全当作模型提升。当前校准Brier为0.000489，历史校准段发生率常数基线为0.001230，技能分为60.22%。同时报告ECE和可靠性曲线。

### 为什么不选验证Brier更低的旧跨窗口校准？

旧方法用不同模型的历史分数拟合映射，然后迁移到新模型，存在分数尺度迁移假设。该方案保留为诊断对照；最终只在同一个冻结基础模型的Platt和Isotonic中按验证Brier选择。没有根据测试Brier反向选择。

### 校准与阈值是否完全独立选择？

校准器拟合使用训练尾段；校准方法和处置阈值都由后续验证段选择，存在重复使用验证段与多重比较的限制。测试独立，报告没有宣称验证结果是无偏估计。

### 阈值搜索为什么是O(n log n)？

先排序并用全部唯一分数作为动作边界。前缀和把各动作区间成本变为O(1)查询，单调队列维护复核容量范围内最优起点，扫描O(n)。排序使总复杂度为O(n log n)，不是无条件线性。48,000行当前机器单次测量0.159秒，且有非默认成本、并列分数的穷举对照测试。

### 成本假设变化会怎样？

每组假设都在验证集重新搜索阈值，再在测试集评估，不是仅把旧成本乘倍率。统一参数对象同时驱动搜索与评估。成本、复核召回和误判率都是演示设定，不能视为线上真实财务值。

### 为什么AP下降与成本上升不能直接归咎于欺诈率？

需要看同一阈值下误差、金额、时段和分布。测试有13笔漏判和47笔误报，漏放损失最高3笔占约88.03%，成本被少量大额样本主导。现有两段数据只支持描述差异，不能证明因果。

### IEEE特征如何防止标签泄漏？

MySQL窗口排除同一秒和未来交易；每一验证月按当期基础模型拟合截止屏蔽更晚标签，再假设7天标签成熟延迟。拟合、早停和校准目标也必须在预测起点前成熟；最终验证选择还需在测试起点前留出7天标签成熟间隔。后续未标注交易的频次可作为在线可观察历史，但验证/测试真实标签永不进入编码。延迟需按真实业务调整。

### 近似uid、WOE、PSI、SHAP有什么限制？

近似uid由card1、addr1和D1推导的首笔相对日拼接，可能混组，不是真实用户；WOE分箱和映射只在训练拟合；PSI参考箱固定于训练；SHAP解释的是已训练模型关联，不证明欺诈原因。当前只有合成IEEE样本验收，不能展示成真实业务发现。

## 5分钟讲稿

**0:00–0:45 问题与数据。** 我做的是极不平衡信用卡交易的离线风险决策：不只是输出分类，还要在有限复核资源下比较放行、复核、拦截成本。真实实验是ULB的284,807笔交易，欺诈492笔，只有约48小时，业务字段匿名，因此我不会把PCA变量解释成设备或商户。

**0:45–1:35 特征与验证。** 我按唯一时间戳做3个扩展窗口，最后15%只测试。金额上比较原值、对数和同时输入两者，LR最终只保留一种，避免共线性影响系数。IEEE扩展代码包含短期频次、历史金额偏离度和新设备特征，但真实数据未提供，我会明确区分代码验收与真实实验。

**1:35–2:25 选型与校准。** LR和XGBoost都用3个候选预算，只用训练内部的早停段决定树数，再看滚动验证AP。最近窗口配对AP区间含0时按事先规则选简单模型。校准改为同一个冻结模型的历史留出预测，比较Platt和Isotonic，校准后不重新拟合基础模型。

**2:25–3:10 效果。** 测试AP为0.7250，95%区间为0.6037–0.8348；ROC-AUC为0.9359。Brier不能只与加权原始概率比较，所以补了历史发生率常数基线，技能分为60.22%。这些区间仍然较宽，测试只有54笔欺诈。

**3:10–4:10 策略与误差。** 在验证集用统一成本搜索双阈值，排序加单调队列使总复杂度O(n log n)。测试沿用冻结阈值，模拟成本为2,547.68，相较全部放行低58.87%，这是演示假设，不能说成线上收益。误差分析发现前三笔大额漏放贡献约88%漏放损失；敏感性分析每组假设重新在验证集选阈值。

**4:10–5:00 不足与下一步。** 本次ROC-AUC低于旧实验；数据时间短、匿名字段多、候选预算有限。下一步是拿到授权IEEE数据，核验近似uid与标签延迟，按相对月做特征消融和漂移，再用真实审核费用校正策略。现在我能提供代码、测试和合成流程验收，但不会把未跑的真实IEEE数字写到简历。

## 窗口SQL手写练习

同卡过去1小时频次，同秒交易不互相提供历史：

```sql
SELECT TransactionID,
       COUNT(*) OVER (
           PARTITION BY card1 ORDER BY TransactionDT
           RANGE BETWEEN 3600 PRECEDING AND 1 PRECEDING
       ) AS card_txn_count_1h
FROM transactions;
```

练习时说明TransactionDT单位为秒、并列时间为何排除，以及“历史交易可见”与“历史标签已成熟”是两个不同条件。不能声称已代替本人完成脱稿练习或现场手写。
