# 交易反欺诈数据挖掘项目：AI 增强规划

## 1. 目标与项目定位

在现有“数据质量检查 → 时间切分 → 类别不平衡建模 → 阈值策略 → 测试集评估”基础上增加一个**智能风控分析助手**。助手读取当前项目生成的结构化报告和有限的测试集结果，为数据挖掘或风控面试场景提供可追溯的自然语言分析：

- 解释 AP、ROC-AUC、Precision、Recall、F1 和混淆矩阵；
- 比较逻辑回归与 XGBoost，并说明为什么由验证集 AP 选择当前模型；
- 解释放行、人工复核、拦截三个动作及复核容量状态；
- 根据报告中的成本假设说明模拟成本变化；
- 回答“为什么测试集没有直接拦截”“匿名特征能不能解释成设备或商户”等项目问题。

AI 只负责报告解读和交互表达。模型训练、指标计算、阈值搜索、成本计算和最终数字仍以 `fraud_model.py` 生成的报告为准，避免大模型改写项目事实。

## 2. 推荐方案与备选方案

### 推荐：结构化报告问答 + 可追溯回答

在看板增加“AI 风控分析”区域。用户输入问题后，程序从 `reports/latest.json`、策略摘要和特征重要性中组装有限上下文，再调用一个 OpenAI-compatible Chat Completions 接口。回答必须引用上下文字段中的数字，并明确区分“报告事实”“成本假设”和“模型解释边界”。

优点是 AI 与现有数据挖掘结果直接关联，演示效果清楚，能够在面试中解释数据流和幻觉控制。接口使用环境变量配置，未配置 API 时显示本地规则摘要，项目仍可离线运行。

### 备选 A：自动生成实验结论卡片

每次训练后生成一页中文结论，不提供自由问答。实现更简单，外部调用更少，但 AI 能力展示较弱，适合没有可用模型服务时使用。

### 备选 B：本地 Ollama 模型

所有问答在本机完成，数据不离开本机。隐私控制更好，但需要额外安装本地模型、占用内存，并且不同机器的回答质量难以复现。除非用户明确已有可用本地模型，否则不作为第一版默认方案。

## 3. 第一版功能边界

### 必须实现

1. 增加 `ai_assistant.py`，负责报告上下文构造、提示词、模型客户端、超时和错误处理。
2. 增加 AI 看板区域，提供问题输入、示例问题、回答和“本次回答使用的报告字段”。
3. 默认读取当前 `reports/latest.json`，只把必要的指标、切分规模、策略结果、成本假设和前 15 个特征重要性放入上下文。
4. 使用项目根目录 `.env` 或系统环境变量配置 `AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL`；系统环境变量优先，项目不保存密钥、不写死供应商、不自动联网。
5. 未配置服务或调用失败时，显示中文离线摘要，并给出清楚的配置提示；不影响原有四个看板页和 `python run.py demo/train`。
6. README 增加 AI 功能运行方式、环境变量示例、支持的问题和限制说明。

### 明确不做

- 不让 AI 重新训练模型、修改阈值或直接执行拦截操作；
- 不把匿名 PCA 特征解释成真实设备、商户、地域或因果因素；
- 不把未校准风险分数称为欺诈概率；
- 不把测试集标签直接拼接到用户可编辑提示词中；
- 不引入向量数据库、复杂 RAG、Agent 工具调用、自动发消息或生产部署；
- 不把外部 API 调用作为离线测试前提。

## 4. 数据流与模块边界

```text
reports/latest.json + reports/test_scores.csv
                     ↓
              报告上下文构造器
                     ↓
       事实约束提示词 + 用户问题 + 字段引用要求
                     ↓
       OpenAI-compatible 模型 / 离线规则摘要
                     ↓
       中文回答 + 使用字段 + 失败提示
```

- `fraud_model.py`：继续负责训练、评估、报告生成，不依赖 AI。
- `ai_assistant.py`：只负责上下文、提示词、HTTP 客户端、响应清洗和离线回退。
- `dashboard.py`：增加 AI 区域，调用助手并展示文本，不直接展示 JSON。
- `run.py`：第一版保持现有 `demo`、`train`、`dashboard` 命令不变；AI 仅作为看板的可选能力，减少入口复杂度。
- `tests/test_ai_assistant.py`：使用 mock 响应测试上下文裁剪、事实引用、超时和离线回退，不访问真实 API。

## 5. 提示词与回答约束

系统提示词应要求模型：

1. 只能使用传入报告中的事实回答；缺少数据时明确说“报告没有提供”；
2. 数字保留报告精度，不能自行重算出另一套结果；
3. 将模型事实、成本假设和业务建议分段表达；
4. 解释特征时主动说明 V1–V28 是匿名 PCA 特征；
5. 不能执行训练、改阈值、导出原始交易或调用未声明工具；
6. 回答末尾列出使用的报告字段，例如“测试集指标、验证集选定策略、成本假设”。

上下文中不放入 API 密钥、原始 CSV 全量内容或不必要的测试集标签。用户问题作为普通文本传入，不允许覆盖系统约束。

## 6. 编码顺序

1. 先实现 `ai_assistant.py` 的纯函数：读取报告、构造上下文、离线摘要、响应解析。
2. 增加可替换的 HTTP 客户端，验证成功、超时、非 200、无效 JSON 和缺失配置路径。
3. 在 Streamlit 看板增加 AI 区域，先接离线摘要，再接可选模型调用；不改变现有结果页。
4. 增加自动化测试和 AppTest，确认未配置 AI 时页面仍能打开，回答中不出现原始 JSON 页面。
5. 更新 README 和简历项目经历，明确“AI 用于报告解读与交互分析”，不夸大为自动风控决策系统。

## 7. 验收标准

- 未配置环境变量时，现有训练、看板、9 项原有测试全部保持通过，AI 区域可显示离线摘要。
- 配置 mock OpenAI-compatible 服务时，能够对至少 5 个示例问题返回中文回答；不要求真实 API 才能通过自动化测试。
- AI 回答至少包含一个来自报告的正确数字，并列出使用字段；报告没有依据的问题返回不确定提示。
- API 超时或返回错误时，页面不崩溃、不泄露密钥，并回退到离线摘要。
- README 能用通用命令说明安装、配置、启动和关闭 AI；不写入本机绝对路径或具体密钥。
- 通过一次完整 `pytest`、一次 Streamlit AppTest 和一次无 API 配置的看板健康检查。

## 8. 风险与后续扩展

第一版的主要风险是模型服务不可用、回答存在幻觉和外部 API 产生费用。通过结构化上下文、字段引用、离线回退、超时和 mock 测试控制这些风险。后续若有真实复核记录，再考虑加入单笔交易解释、反馈闭环、提示词评估和回答质量基准；当前不提前建设。
