## 0. 结论

评估流程已经比多数学生项目规范：按时间滚动验证，测试集隔离，阈值在验证集冻结，并给出 Bootstrap 区间、配对差异检验、Platt 校准和 Wilson 区间。统计专业的优势已经体现出来。

拉低竞争力的问题按优先级排序：

1. **招聘方看不到这些改进。** 远端 HEAD 没有 Bootstrap、校准和卡方检验，最新提交信息与代码不符；截图（11-05）早于报告（11-14）；线上看板缺逐笔分数，可靠性曲线显示为空。
2. **几处统计和实现细节经不起追问。** 阈值搜索的成本参数写死，敏感性分析没有重新搜索阈值；校准器拟合用的分数来自另外两个窗口的模型；Brier 改善的表述有误导；“线性复杂度”的说法与实测不符。
3. **数据挖掘岗最看重的特征工程基本空白。** 特征只新增了 `LogAmount`，IEEE-CIS 的窗口 SQL 仍是模板，没有在真实数据上跑出结果。

建议顺序：先花 1–2 天把现有成果同步到 GitHub，再用约 1 周修正统计细节，然后用 2–3 周接入 IEEE-CIS 做特征工程主线。总投入约 5–6 周，每周 15 小时左右。

### 阶段 1：修正统计与实现细节（约 1 周，P1）

| 任务 | 做法 | 验收 |
|------|------|------|
| 1.1 成本参数统一 | 新建一个成本参数对象（dataclass 或 dict），`choose_policy` 和 `cost_of_actions` 共用 | 改一个参数，阈值和成本同时变化；现有的暴力搜索对比测试加上非默认参数 |

| 1.3 敏感性分析重新决策 | 每组成本假设都在验证集上重新搜索阈值，再到测试集评估；输出阈值、复核率和成本 | 热力图能看出哪些假设下策略会变；README 改写复杂度表述 |
| 1.4 校准方案对比 | 方案 A：现有做法。方案 B：在窗口 3 的训练段内部再按时间切出一段拟合校准。方案 C：Isotonic。比较 Brier、ECE 和可靠性曲线 | 选择有数据依据，并在报告里说明 |

| 1.7 公平调参 | 两个模型给相同的调参预算（例如 Optuna 各 30 次），只在滚动验证窗口上调，XGB 用验证段早停 | “差异不显著选 LR”的结论建立在调参后的比较上 |

### 阶段 2：接入 IEEE-CIS，做特征工程主线（2–3 周，P0）

ULB 的结果保留为“对照实验”一节，项目主线换成 IEEE-CIS（约 59 万笔、约 6 个月、带卡、地址、邮箱、设备字段）。

| 任务 | 做法 | 验收 |
|------|------|------|
| 2.1 数据接入 | 合并 transaction 和 identity 表后转成 parquet；先用 10 万行样本调通流程 | `data/ieee.source.json` 记录来源和 SHA-256 |
| 2.2 近似用户 ID | 用 `card1 + addr1 + (D1 换算的首笔交易日)` 构造 uid，统计每个 uid 的交易数分布，抽查其中的欺诈标签一致性 | 报告注明这是近似 ID，并说明构造思路参考了比赛公开讨论 |
| 2.3 特征分组实现 | 复用现有 5 条窗口 SQL，在全量数据上运行：频次/速度、金额偏离度、新颖性、频率编码、平滑目标编码，再加上真实小时和星期 | 至少 25 个新特征；防泄漏测试从 4 行合成表扩展到真实样本抽查 |
| 2.4 特征筛选 | 依次看缺失率、IV、按月 PSI | 输出筛选表，每个被剔除的特征都写明原因 |
| 2.5 分组消融 | 基础字段 → +频次 → +偏离度 → +新颖性 → +编码，每一步给出 AP 增量和配对 Bootstrap 区间 | 能说清哪组特征有效、哪组不显著 |
| 2.6 建模 | 按月扩展窗口验证，最后一个月只测试一次；对比 WOE 评分卡、LightGBM、XGBoost | 测试 AP 带 95% 区间；与比赛公开的 LightGBM 基线对照，说明差距来源 |
| 2.7 解释 | SHAP 全局图，再选真阳性、漏判、误报各 1 例画 waterfall | 能用业务语言讲清楚每个案例 |
| 2.8 漂移 | 按月计算特征和分数的 PSI、月度 AP；比较“训练一次”和“每月重训” | 能回答“多久需要重训”，并给出数据依据 |

## 3. 不建议做的事

- 继续扩展 AI 助手：对数据挖掘岗加分有限，保留现状即可。
- 深度学习表格模型、K8s、在线监控平台：实习面试讲不深，反而会被追问。
- 把 SMOTE 作为主方案：会破坏概率校准，最多做一组对照。
- 在 ULB 数据上编业务故事：V1–V28 是匿名 PCA 分量，现有文档在这一点上很克制，应继续保持。
